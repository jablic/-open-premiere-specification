# UXP Panel Scaffold & Manifest v5

> Minimal, production-ready scaffolding for UXP panels in Premiere Pro 25.6+. Covers `manifest.json` v5, permission model, Spectrum Web Components baseline, and runtime lifecycle.

## TL;DR
- **Manifest v5** replaces CEP's `.csxs`. Permissions are declarative (`requiredPermissions`).
- **No Chromium bridge**: UI and logic run in a single sandboxed JS engine. `require('premierepro')` gives async DOM access.
- **Spectrum Web Components** are the only supported UI primitives. No raw HTML/CSS hackery.
- Distribution: `.ccx` via UPIA or Adobe CC Marketplace. Signing handled by Adobe's toolchain.

## Status & Lifecycle
- `current`. Requires **Premiere 25.6+**. CEP is no longer relevant for new panels.
- Manifest format is stable in v5; watch Adobe's developer blog for permission model tweaks.

## Architecture
```
panel/
├── client/
│   ├── manifest.json        # UXP v5 manifest
│   ├── index.html           # Entry point (loads /dist/bundle.js)
│   └── dist/                # Compiled UI bundle (Webpack/Vite)
├── main.js                  # UXP JS logic (premierepro DOM, fs, os)
├── .uxp                     # Optional: UXP dev config
└── package.json             # Dependencies (spectrum-web-components, etc.)
```

## API Surface & Patterns

### `manifest.json` v5 skeleton
```json
{
  "id": "com.yourname.premiere-uxp-panel",
  "name": "My UXP Panel",
  "version": "1.0.0",
  "main": "client/index.html",
  "requiredPermissions": {
    "network": true,
    "fileSystem": "restricted"
  },
  "host": [
    {
      "name": "PPRO",
      "minimumVersion": "25.6"
    }
  ]
}
```

### UI Skeleton (Lit + Spectrum)

  <sp-heading>Panel Title</sp-heading>

## Working Examples

### Main JS Logic (UXP)
```js
// main.js — UXP runtime (Modern JS + async/await)
const ppro = require('premierepro');
const { Event } = require('uxp');

document.getElementById('render-btn').addEventListener('click', async () => {
  const project = await ppro.Project.getActiveProject();
  if (!project) { alert('No project open.'); return; }

  const seq = await project.getActiveSequence();
  if (!seq) { alert('No active sequence.'); return; }

  try {
    // UXP mutations must be wrapped in executeTransaction
    await project.executeTransaction(async (tx) => {
      const preset = await ppro.Preset.findByFormat('H264');
      await seq.exportAsMediaDirect('/tmp/render.mp4', preset);
    }, 'Export Sequence to H.264');
  } catch (err) {
    console.error('Export failed:', err.message);
  }
});
```

## Limitations
- No raw DOM access outside `<iframe>` or Spectrum components.
- `requiredPermissions` are binary; granular file paths must use `uxp.storage.persistentStoragePath`.
- UXP panels cannot run headless. Premiere UI must be active.

## Common Errors & Gotchas
- **Symptom:** Panel fails to load with `Permission Denied`.
  **Cause:** Missing or mismatched `requiredPermissions` in manifest vs code usage.
  **Fix:** Sync manifest exactly with runtime requirements. Use UDT for validation.
- **Symptom:** Spectrum components render incorrectly.
  **Cause:** Loading order issues or missing polyfills in older browsers (rare on 25.6+).
  **Fix:** Ensure `import 'spectrum-web-components/bundle.js';` at entry point.

## Workarounds
- **Legacy CSS fallback:** Wrap non-Spectrum UI in an `<iframe>` and inject styles via CSP-compliant `<style>`.
- **File access beyond sandbox:** Use `uxp.storage.persistentStoragePath` or request `fileSystem: "readwrite"` if truly needed (requires marketplace review).

## Migration
CEP → UXP is a full rewrite. Drop `CSInterface`, `manifest.xml`, and Chromium bridge logic. Map synchronous ExtendScript calls to async `await` methods. Replace Spectrum components for all UI. File gaps on Adobe Developer Forums.

## Cross-References
- `uxp` — core runtime & DOM
- `cep` — legacy panel architecture (for comparison)
- `debugging` — UDT v2.2.1+ usage
- `00-technology-status-matrix` — version authority

## Sources
- https://developer.adobe.com/premiere-pro/uxp/resources/manifest-v5-reference/
- https://developer.adobe.com/premiere-pro/uxp/resources/fundamentals/apis/

# UXP MOGRT Text Injection Gap & Fallback Patterns

> UXP **does not yet expose** direct `getValue()`/`setValue()` on the Source Text JSON blob at parity with ExtendScript. This doc provides production patterns to bridge that gap until Adobe ships full UXP text-blob access.

## TL;DR
- **Gap confirmed:** UXP 25.6 lacks low-level MOGRT property mutation APIs.
- **Workaround:** Use a CEP/ExtendScript host-side patcher + `CSInterface` bridge (if targeting mixed install base), or wait for Adobe's parity update.
- **Safe pattern:** Keep blob-patching logic isolated in an ES3 `.jsx` file; invoke from UXP via `evalScript` only when text mutation is strictly required.

## Status & Lifecycle
- `mixed`. UXP panel UI runs in JS/TS, but MOGRT patching falls back to ExtendScript for now.
- Gap is tracked officially by Adobe; parity expected in future 26.x cycles.

## Architecture
```
UXP Panel (main.js) → [UI / Async DOM Ops]
         ↓ (if text mutation needed)
[evalScript bridge] → Host script (patch-mogrt.jsx, ES3 + json2.js)
         ↓
Patches TrackItem → ComponentParam → Source Text Blob → UI refresh
```

## API Surface & Fallback Patterns

### Step 1: UXP Side — Queue the mutation
```js
// main.js (UXP)
const cs = new CSInterface(); // Only if CEP runtime is still loaded; otherwise use direct bridge if available
async function patchTextFromUXP(trackItemRef, newText) {
    const args = JSON.stringify({ ref: trackItemRef, text: newText });
    return new Promise((resolve) => {
        cs.evalScript(`patchMogrtText(${args})`, (raw) => {
            try {
                resolve(JSON.parse(raw));
            } catch {
                resolve({ ok: false, err: raw });
            }
        });
    });
}
```

### Step 2: Host Side — ES3 Patcher (safe bundle)
```js
// patch-mogrt.jsx (ES3 + json2.js)
//@include "json2.js"
function patchMogrtText(args) {
    try {
        var p = JSON.parse(args);
        var seq = app.project.activeSequence;
        if (!seq) return JSON.stringify({ ok: false, err: "No seq" });

        // Locate clip by ref (ID or name)
        var clips = seq.videoTracks[0].clips;
        var target = null;
        for (var i = 0; i < clips.numItems; i++) {
            if (clips[i].name === p.ref || clips[i].id === p.ref) {
                target = clips[i]; break;
            }
        }
        if (!target) return JSON.stringify({ ok: false, err: "Clip not found" });

        var comp = target.getMGTComponent();
        if (!comp) return JSON.stringify({ ok: false, err: "Not a MOGRT" });

        var param = comp.properties.getParamForDisplayName("Source Text");
        if (!param) return JSON.stringify({ ok: false, err: "Param missing" });

        var blob = JSON.parse(param.getValue());
        blob.textEditValue = p.text;
        blob.fontTextRunLength = [p.text.length]; // MANDATORY

        param.setValue(JSON.stringify(blob), true);
        return JSON.stringify({ ok: true });
    } catch (e) {
        return JSON.stringify({ ok: false, err: String(e) });
    }
}
```

## Limitations
- Bridge adds latency and requires CEP runtime compatibility.
- `fontTextRunLength` must be updated on every change; failure causes blank/shifted text.
- UXP-only installations (25.6+ without legacy bridge) cannot run this fallback.

## Common Errors & Gotchas
- **Symptom:** `CSInterface is undefined`.
  **Cause:** UXP runtime in pure 25.6+ doesn't bundle CEP libraries by default.
  **Fix:** Only use bridge if targeting mixed installs, or compile a minimal CEP host into the extension bundle.
- **Symptom:** UI refresh delay after patch.
  **Cause:** Caching bug #4221638 (recurrent in 24.x/25.x).
  **Fix:** Pass `true` to `setValue`; force a timeline render or nudge clip offset.

## Workarounds
- For UXP-only targets: expose the mutation logic as a native UXP module once Adobe ships it; currently, file the gap on the Creative Cloud Developer Forums.
- Use After Effects Export → Media Encoder pipeline for heavy graphics automation instead of in-PPro patching.

## Migration
Once UXP exposes `MogrtComponentParam.setValue()`, remove the bridge. Isolate host logic in a single `uxp-fallback-mogrt.js` file; future port will be a simple `require` swap.

## Cross-References

- `00-technology-status-matrix` — version authority

# Advanced FCPXML/FCP7 Parsing & Path Resolution

> Premiere exports legacy FCP7 XML (xmeml) and modern FCPXML. While `exportAsFinalCutProXML` handles the round-trip, parsing requires handling `<pathurl>` resolution across master/clipitem references, Base64-embedded graphics text, and strict timecode-to-ticks mapping.

## TL;DR
- **Path Resolution:** `<pathurl>` often appears only on the first `<clipitem>` for a `file id`. Subsequent clipitems reference by `id` only. Resolve via `<name>` + `<file id>`.
- **Time Mapping:** Convert frames ↔ seconds using `<rate><timebase>` per sequence/clipitem scope. Use `254016000000` ticks/sec as the internal anchor.
- **Graphics Text:** Often buried in `<filter>/<effect>` → `<data>` as Base64. Decode permissively; filter noise via Unicode letter ranges.
- Use `opentimelineio.adapters.fcp_xml` for structural reconstruction; manual parsing is only needed for metadata/graphics extraction.

## Status & Lifecycle
- `current`. Interchange format remains actively supported. DTD versions (`dtd-version="1.5"` etc.) dictate schema variations.

## Architecture
```xml
<xmeml dtdversion="1.4">
  <sequence>
    <media><video><track><clipitem id="v2_1" masterClipId="mc_1"...>
      <file id="f1"><pathurl>file:///.../clip.mp4</pathurl></file>
      <filter><effect>...<data>B64_ENCODED_BLOB...</data></filter>
    </sequence>
</xmeml>
```

## API Surface & Parsing Patterns (Python)
```python
import xml.etree.ElementTree as ET
import base64
import re

def resolve_pathurls(root: ET.Element):
    """Build a {file_id: pathurl} map, handling first-writer semantics."""
    files = {}
    for f in root.iter("file"):
        fid = f.attrib.get("id")
        url = f.findtext("pathurl")
        if fid and url:
            files[fid] = url  # last one wins, but first usually correct
    return files

def extract_base64_graphics(root: ET.Element) -> list[dict]:
    """Recover text candidates from filter/effect data nodes."""
    hits = []
    for fx in root.iter("filter") + root.iter("effect"):
        data_nodes = fx.iter("data")
        for d in data_nodes:
            raw = d.text or ""
            if not re.match(r"^[A-Za-z0-9+/=]{8,}$", raw.strip()):
                continue
            try:
                decoded = base64.b64decode(raw).decode("utf-8", errors="ignore")
                tokens = re.findall(r"[A-Za-z\u00C0-\uFFFF]{3,}", decoded)
                hits.extend(tokens)
            except Exception:
                continue
    return list(dict.fromkeys(hits))  # dedupe preserving order

def frames_to_tc(frames, fps):
    f = int(frames) if frames else 0
    s, ff = divmod(f * 1000, round(1000/fps))  # millisecond precision safety
    h, rem = divmod(s // 1000, 3600)
    m, sec = divmod(rem // 1000, 60)
    return f"{h:02d}:{m:02d}:{sec:02d}:{ff:02d}"
```

## Limitations
- Base64 text is highly fragile; flattened or compressed graphics often lose metadata.
- `pathurl` resolution can be inconsistent if Premiere renames/moves media post-export.
- DTD version changes silently alter node names (`<generatoritem>` vs `<video>` structure).

## Common Errors & Gotchas
- **Symptom:** Media relink fails after import.
  **Cause:** `<pathurl>` only on master clip, but project expects it on all clipitems.
  **Fix:** Merge `files` map; fallback to relative paths if absolute breaks sandbox rules.
- **Symptom:** Timecodes drift by frame or drop frames incorrectly.
  **Cause:** Using raw `<timecode>` string instead of `<rate><timebase>`.
  **Fix:** Always compute: `seconds = int(in_frame) / float(timebase)`.

## Workarounds
- For reliable project reconstruction, use `opentimelineio`: `otio.adapters.fcp_xml.read_from_file("export.xml")`.
- If Base64 decoding fails, log the raw blob and fall back to UI inspection; FCPXML is not a source-of-truth for Essential Graphics.

## Migration
- Export via UXP: `await seq.exportAsFinalCutProXML(path)` (returns boolean, async).
- Parse with `lxml` or `ET`; avoid DOMParser in browser due to namespace resolution bugs.
